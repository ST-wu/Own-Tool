# Agent Workspace Rules - Optimized V21 (優化組 V21 設定)

## 1. 📂 備份生命週期與實體安全閘 (Lifecycle & Safety Gates)
* **會話隔離備份**：修改程式碼前，**必須**確認隔離區 `.agents/backups/` 中無同會話備份。備份命名格式必須為：`.agents/backups/<relative_path_to_file>.<session_id_hash>.bak` *(session_id_hash 取對話 ID 後五碼)*。
* **還原退避與原子清理**：若修改失敗且同回合內無法修復，**AI 必須主動將備份還原覆蓋，撤銷髒污變更**。若任務成功且測試通過，必須在同回合中主動刪除該會話備份。若實施拓撲剪枝，單元測試驗證與備份清理自動順延至 TODO 消費者全數修改完畢的最終回合。
* **物理雙向驗證**：若執行 `python auditor.py` 報錯或缺失，必須降級為人工自審。自審時**嚴禁虛報**，必須調用 `view_file` 或 `run_command` 的 OS 指令實體確認備份檔案大小，並在自檢 Checklist 中寫明：`[ ] 備份已隔離 (確切檔案大小, verified via view_file)`。
* **敏感目錄旁路阻斷**：非敏感目錄下小於 3 行的非邏輯修改（如 `.md` 文檔、排版、註解）允許跳過雙軌 PLAN 與自審。**敏感目錄（如核心交易、多線程、鎖邏輯等）之任何修改，嚴禁使用智能旁路。**

## 2. 🧠 代碼健康與變更控制 (Clean Code & Change Control)
* **Guard Clauses 優先**：編寫高風險操作時，必須使用 `try-except/try-catch` 防護。**嚴禁將整個函數主體包裹在單一巨大的 try 區塊中**。try 區塊必須僅包裹最窄的高風險行，其餘業務判斷應使用提早退出 (Guard Clauses) 以維持代碼乾淨。
* **變更最小化與 multi_replace**：修改代碼必須只變更與問題直接相關的行數（Git Diff 最小化），嚴禁無意義的重排格式。讀取檔案必須限制行數；在同檔案中有多個不連續修改點時，**必須優先使用 `multi_replace_file_content` 一次性完成取代**。
* **依賴引入與精準日誌**：引入新外部依賴前，必須確認環境已安裝，並寫入 requirements.txt/package.json。若環境未安裝，優先調用工具安裝；若無網路/權限安裝失敗，必須在 PLAN 中提示使用者手動安裝。嚴禁使用無日誌的 `except Exception: pass`。如果使用寬泛捕獲，必須輸出至少一行帶有 `[ERROR_SUMMARY]` 與 `type(e).__name__` 的錯誤核心摘要。

## 🎯 3. 設計決策優先與拓撲開發 (Design Priority & Pruning)
* **方案折疊與失敗分析 (FMA)**：
  - 除修復邏輯極為明確（單一 config 修改、拼字修正、單一語意修復）可免除對比直接進行單軌宣告外，其餘邏輯變更默認必須在 [PLAN] 中進行方案 A/B 雙軌對照。
  - **顯式失敗模式分析 (FMA)**：在方案 B（防禦性重構）中，必須顯式列出該方案在以下 3 個極端情境（併發、網絡故障/超時、空值/邊界值）下會如何失效。嚴禁脫離當前架構進行無意義的學術窮舉，確保 YAGNI 實用性。
  - 只有在面臨架構重構、併發死鎖、多模組接口簽名變更等高風險任務時，才必須暫停並等待使用者批准。
* **拓撲剪枝與分步開發**：若接口變更的呼叫端 (Consumers) 超過 3 個，必須實施「拓撲剪枝」，首回合僅重構底層模組與最核心 of 2-3 個呼叫端，其餘 Consumers 留作 TODO 清單並在後續回合中遞歸重構。若 Consumers 未滿 3 個，則由底層模組開始依拓撲順序在同回合內同步重構。

## 💬 4. 認知節流、極簡通訊與分級自適應 (Cognitive & Safety Exceptions)
* **模型分級降級約束**：若當前執行之 LLM 為 Lite 系列模型 (如 gemini-*-flash-lite)，自動啟動「精簡模式」以釋放注意力：
  1. 免除 `[PLAN]` 中的雙軌對比（僅進行單軌宣告）。
  2. 免除 `auditor.py` 行為審計，直接降級為人工思維自檢。
  3. 優先使用窄 scope 的 `replace_file_content`。
* **極簡對話與安全警示例外**：常規公開發言限制在 2 句話或 100 字內且無客套話。但當需要呈報 Benchmark 對比報告、Mermaid 架構圖、手動執行指南，或面臨高風險高歧義操作時，**自動免除字數與社交詞約束**，以展示結構化資訊並引導用戶使用 `/grill-me` 進行安全對齊。
